# 原型输出skill

## 一句话安装

```text
帮我安装这个 skill：https://github.com/vinsonhi/AI-Skills/tree/main/skills/prototype-output-skill
```

一个用真实后台页面做高保真 HTML 原型的 skill。

**理念：** 先读取现网页面的运行态 DOM、CSS 和组件结构，再基于现网组件做需求迭代。不要从截图或记忆里重画一个“像后台”的页面。

## 一句话使用

```text
用原型输出skill，基于我当前打开的后台页面，先抓运行态 DOM/CSS，再按我的需求做高保真 HTML 原型，并导出可分享的单文件。
```

## 适合什么

- 已有后台页面上的需求原型
- 数据看板、经营后台、管理后台的高保真迭代
- 新增指标、筛选、视图、表格字段、AI 总结等模块
- 需要和产品、设计、研发、业务方讨论的可点击 HTML 原型
- 需要分享给别人，但不想依赖线上环境才能打开的单文件原型

不适合：

- 从零设计官网、活动页、品牌站
- 完全没有现网页面参考的新产品探索
- 已有 Figma 高保真稿，只需要按稿还原的任务

## 它会做什么

1. 打开或读取你提供的后台页面。
2. 抓取已登录页面的运行态 HTML、截图、computed style、关键类名、组件结构和资产来源。
3. 生成组件来源表，说明 header、侧边栏、Tab、按钮、卡片、表格、图标分别来自哪个线上 selector/class/asset。
4. 保留线上顶部导航、侧边栏、Tab、筛选、卡片、表格、按钮和操作列。
5. 基于需求做增量或结构性改造，而不是套通用后台模板。
6. 复用线上表格密度、分组表头、固定列、排序、展开收起和操作按钮。
7. 对真实团队名、用户信息、ID、外部不可见经营数据等内容做脱敏和禁用字段检查。
8. 导出 standalone HTML，减少分享后样式、图片、脚本丢失。
9. 用来源门禁、视觉对照门禁、源码搜索门禁做最终验收，不通过就返工。

## 关键原则

### 先读真实页面

对现代前端应用来说，静态入口 HTML 通常不够，运行态 DOM 才是原型基准。

开始做原型前，必须先确认：

- 顶部 banner、顶部 Tab、账号区是否还在
- 左侧目录、选中态、图标和背景色是否和线上一致
- 卡片、按钮、筛选器、日期组件是否沿用现网样式
- 图标是否来自现有页面或同类组件
- 表格是否保留分组表头、固定操作列、排序、展开收起和横向滚动
- 折线图、图例、坐标轴、选中卡片联动是否还存在

必须保存这些过程文件：

- `live-runtime-dom.html`：运行态 DOM，不是静态入口 HTML
- `live-screenshot.png`：线上页面截图
- `computed-style.json`：header、侧栏、tab、按钮、卡片、表格等核心组件的实测样式
- `asset-inventory.json` 或 `asset-inventory.md`：线上 logo、菜单 icon、SVG、图片、图表资产来源
- `provenance-map.md`：最终原型每个核心区域对应的线上 selector/class/asset
- `visual-review.md`：线上截图和原型截图逐项对照

没有这些证据，不应该交付原型。

### 来源门禁

原型不是重新设计页面，而是在真实运行态 DOM 上做产品迭代。

最终原型里的核心区域必须能回答这些问题：

- Header/banner 来自哪个线上 selector？logo 用的是哪个线上 asset？
- 侧边栏来自哪个线上 selector？菜单 icon 是否来自线上 SVG？
- 顶部 Tab 是否沿用线上 tab class、间距、下划线和选中态？
- 按钮是否沿用线上按钮高度、颜色、圆角和 padding？
- 卡片、表格、输入框、分页是否沿用线上组件密度？
- 哪些地方因为需求变化做了重构？是否记录了原因？

如果某个区域没有线上来源证明，默认视为不合格。

### 基于现网组件迭代

新需求要放在合适的产品层级里：

- 页面级能力放页面区域
- 视图级总结放对应视图里
- 表格字段变更保留原表格语义
- 已有入口如「设置目标」「导出数据」默认继续复用
- 切换视图时不随便重置用户已经展开的层级

实现优先级：

1. 保留线上 DOM 子树，只替换内容。
2. 用线上 selector/class/asset 和 computed style 重建组件。
3. 只有线上资产不可用或敏感时，才使用中性占位，并在 `provenance-map.md` 说明。

禁止只靠截图重画 header、banner、侧边栏、tab、按钮、表格、图表。

### 分享前做单文件处理

分享版 HTML 至少要检查：

- 没有外链脚本依赖
- 没有必须依赖外部加载的样式表
- 没有会影响资源路径的 `base href`
- 图片已转成 `data:` 或替换为占位图
- 没有真实名称、ID、鉴权图片 URL 等敏感信息残留
- 面向外部用户时，没有收入、在线人数、付费人数、礼物数、房间 ID、账号 ID 等不可展示字段

部分 IM、文档或知识库平台会过滤 HTML 里的 `<script>`。遇到这种情况，发送原始 `.html` 文件或 zip 附件，不要直接粘贴 HTML 内容。

## 常见踩坑

- 只看截图不读 DOM/CSS，容易把 banner、侧边栏、背景色、按钮样式都画错。
- 抓了 DOM 但最后仍然手写一套壳，等同于没用真实页面。
- 用自绘图标替代线上菜单 SVG，容易做出 checkbox、通用后台或不属于产品的样式。
- 靠隐藏逻辑删组件，容易留下旧 DOM；优先从生成代码或结构层面处理。
- 表格字段改造不能随便删列，分组表头和固定操作列很容易错位。
- 视图切换不能把用户已经展开的团队层级关掉。
- 原型分享前不做单文件处理，别人打开会丢样式、图标、头像和折线图。
- 截图验证只看“页面出来了”，没有和线上截图逐项对照，明显差异会漏掉。

## 最终验收清单

交付前必须确认：

- 已保存 `live-runtime-dom.html`
- 已保存线上截图和原型截图
- 已保存 computed style 和 asset inventory
- 已完成 `provenance-map.md`
- 最终 HTML 能 grep 到线上 shell/component 的关键 class 或 selector
- 线上 logo、菜单 icon、核心 SVG 已内联或有明确替代说明
- 没有外链脚本、必须外链样式、`base href`
- 没有真实名称、ID、鉴权图片 URL、外部不可见经营数据
- `visual-review.md` 里 header、banner、侧栏、tab、按钮、表格没有未解决 mismatch

```

```

## 手动安装

```bash
git clone https://github.com/vinsonhi/AI-Skills.git
cp -R AI-Skills/skills/prototype-output-skill <你的-agent-skills目录>/
```

如果你的工具使用不同的 skill 目录，把 `prototype-output-skill` 复制到对应目录即可。
