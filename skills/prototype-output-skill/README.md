# 原型输出skill

一个专门用来做「现网后台页面高保真原型迭代」的 AI Skill。

它不会从空白页面重画一个看起来像后台的假界面，而是先读取你给的真实后台页面，抓取运行态 DOM、CSS、组件层级和交互结构，再基于现网组件做需求改造，最后输出一个可以分享的 HTML 原型。

**理念：** 做产品迭代原型时，真实页面是原型的地基。先尊重线上组件、信息架构和交互习惯，再把新需求放到正确的位置。

## 你会得到什么

使用这个 skill，Codex 会默认帮你处理这些事：

- 打开或读取你提供的后台页面 URL
- 抓取已登录页面的运行态 HTML、CSS、关键类名和组件结构
- 保留线上顶部导航、侧边栏、Tab、筛选、卡片、表格、按钮和操作列
- 基于你的需求做增量或结构性改造，而不是套一个通用后台模板
- 复用线上表格密度、分组表头、固定列、排序、展开收起和操作按钮
- 对真实公会名、团队名、用户信息、ID 等内容做脱敏
- 导出一个更适合分享的 standalone HTML，减少样式、图片和脚本丢失

## 适合什么场景

适合做：

- 内部后台页面的需求原型
- 数据看板、经营后台、管理后台的高保真迭代
- 已有页面上新增指标、视图、筛选、表格字段、AI 总结等模块
- 需要和设计、研发、业务方讨论的可点击 HTML 原型
- 需要分享给别人，但不想依赖线上环境才能打开的单文件原型

不适合做：

- 从零设计官网、活动页、品牌站
- 完全没有现网页面参考的新产品探索
- 已经有 Figma 高保真稿，只需要按设计稿还原的任务


或者更具体一点：

```text
用原型输出skill，打开我当前浏览器里的后台页面，保留线上导航、卡片和表格样式，在表格上方新增一个 AI 总结模块，并导出可分享的单文件 HTML。
```

```text

```

## 它会怎么做

### 1. 先读真实页面

Skill 会要求 Codex 先从真实页面拿上下文：

- 页面壳子：顶部导航、侧边栏、面包屑、Tab、页脚
- 组件样式：按钮、卡片、筛选器、日期选择、空状态、分页
- 表格结构：分组表头、固定列、操作列、排序样式、行高
- 交互结构：展开收起、下钻、视图切换、导出、设置目标等

对现代前端应用来说，静态入口 HTML 通常不够。运行态 DOM 才是原型基准。

### 2. 再做需求迭代

Codex 会把你的新需求放到合适的产品层级里：

- 页面级能力放页面区域
- 视图级总结放在对应视图里
- 表格字段变更保留原表格语义
- 已有入口如「设置目标」「导出数据」默认继续复用
- 切换视图时不随便重置用户已经展开的层级

这能避免常见问题：顶部 Tab 丢失、侧边栏丢失、按钮样式变了、表格操作列错位、页面看起来像重新造了一套。

### 3. 最后导出可分享 HTML

如果你要分享给别人，Skill 会要求 Codex 做分享前处理：

- 去掉外链脚本依赖
- 内联必要样式
- 去掉会影响资源路径的 `base href`
- 图片转成 `data:` 或替换为占位图
- 检查是否还有真实名称或敏感信息残留
- 本地打开验证交互和布局

注意：有些 IM、文档或知识库平台会主动过滤 HTML 里的 `<script>`。这种情况下，应该发送原始 `.html` 文件或 zip 附件，而不是把 HTML 内容直接粘到文档里。

## 使用示例

```text
用原型输出skill，基于我当前打开的经营数据后台页面，新增一个 AI 总结模块。样式要沿用线上页面，表格和筛选器不要重画。
```

### 表格字段升级

```text
用原型输出skill，基于这个页面做表格字段改造。保留线上分组表头、固定操作列和展开收起能力，新增同比/环比字段，并输出可分享 HTML。
```

### 现网页面复刻后改造

```text
用原型输出skill，先抓取这个后台页面的运行态 HTML 和 CSS，再根据我的需求改卡片顺序、指标文案和视图切换逻辑。
```

## 工作原理

1. 从真实页面或用户当前浏览器获取运行态 DOM
2. 记录线上组件结构、字段、样式和交互
3. 在本地生成 HTML 原型或生成脚本
4. 按需求修改对应模块
5. 脱敏真实业务数据
6. 导出 standalone HTML
7. 打开本地 HTML 做视觉和交互校验

## 隐私和安全

- 这个 skill 本身不包含任何私人 PRD 写作规则
- 不内置公司、团队、公会或业务数据
- 要求最终原型交付前做脱敏检查
- 对需要登录的内部页面，默认使用你已经登录的浏览器环境，不要求把账号信息写入配置
- 生成的可分享 HTML 应避免保留真实用户、团队、ID 和鉴权图片 URL
