# 小红书研究 Skill

一句话安装：

```text
帮我安装这个 skill：https://github.com/vinsonhi/AI-Skills/tree/main/skills/xiaohongshu-research
```

如果你的 Codex 支持从 GitHub 路径安装，直接说上面这句就够了。

脚本依赖：

```bash
cd skills/xiaohongshu-research/scripts
npm install
```

## 你会得到什么

这是一个让 Codex 用已登录的小红书做真实用户研究的 skill。它不是只看搜索结果标题，而是会打开笔记、读正文、看评论、看图片/视频线索，并检查作者主页来判断内容可信度。

适合用来研究：

- 旅游避坑、城市攻略、餐厅体验
- 消费品真实口碑
- 医美、健身、穿搭、母婴等强种草领域
- 某个品牌、产品、店铺在小红书上的用户反馈
- 评论区里反复出现的真实痛点和争议

它会特别注意过滤营销内容，避免把商家号、代发号、纯种草文当成普通用户反馈。

## 怎么使用

直接给研究问题：

```text
帮我在小红书研究一下“东京亲子酒店”，重点看真实用户踩坑和推荐理由
```

也可以指定范围：

```text
帮我看小红书上大家怎么评价某某品牌的防晒，重点区分真实用户反馈和营销号
```

如果你要更严谨的样本：

```text
至少分析 30 篇笔记，分清正文证据、评论证据、图片/视频证据，最后给我可信结论和争议点
```

## 它会怎么做

这个 skill 默认会让 Codex：

- 先在搜索页筛候选，不按排名机械打开前几条
- 详情页优先走移动端视图，绕开桌面端常见的笔记不可浏览限制
- 使用持久化登录态，减少重复扫码
- 同时看正文、评论、图片、视频帧和作者主页
- 区分“原帖说的”和“评论区说的”
- 记录样本数量、评论数量和证据来源
- 用营销风险规则下调可疑笔记权重

## 输出会长什么样

最终结果会更像一份研究简报，而不是泛泛总结：

```markdown
这轮小红书我主要看的是“海鲜市场怎么买不踩坑”，重点看了正文、评论、图片和作者主页，结论先给你：

## 可信结论

- 最稳定的建议不是“去哪家最便宜”，而是先问清计价方式、加工费、是否足斤足两。
- 真正有参考价值的帖子，通常会给出价格、品类、人数、加工方式、最终总价这些硬信息。

## 争议点

- “凌晨去最新鲜”评价分化明显，普通游客未必值得为这点差异专门早起。

## 营销风险

- 一部分账号主页长期只发固定市场或固定商户，营销嫌疑偏高。

## 证据样本

- 样本 A：正文给出 4 人用餐，总价 680，评论区 7 条在讨论“加工费偏高”。
- 样本 B：图片拍到了摊位价签和称重过程，可信度较高。
```

## 准备工作

安装浏览器和视频处理工具：

```bash
brew install --cask google-chrome
brew install ffmpeg
```

如果要复用你本机 Chrome 的小红书登录态，可以设置：

```bash
export XHS_CHROME_USER_DATA_DIR="$HOME/Library/Application Support/Google/Chrome"
export XHS_CHROME_PROFILE_DIRECTORY="Default"
```

如果不设置，脚本会使用自己的持久化 profile。第一次登录后，后续通常不需要反复扫码。

## 可信度规则

更可信的内容通常有：

- 具体价格、日期、路线、人数、限制条件
- 图片或视频里能看到现场细节
- 正负面混合表达
- 作者主页主要是日常内容，而不是长期只发同一类产品/地点

风险更高的内容通常有：

- 账号名、简介、主页内容和搜索主题高度绑定
- 明显 booking / 私信 / 团购 / 引流话术
- 全文只有夸奖，没有操作细节
- 评论区有人引导私聊或加联系方式
