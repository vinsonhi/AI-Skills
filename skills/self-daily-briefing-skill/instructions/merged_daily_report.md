# Morning Brief 标准日报说明

## 目标

生成默认完整 Morning Brief：包含综合早报、财经早报、AI 日报、美股股票早报。默认使用 `lark-doc` skill 在用户的飞书个人空间创建一篇飞书文档，并把飞书文档链接交付给用户；不再默认输出 Markdown 文件或 PDF 文件。

## 严格规则

1. 先生成或读取各板块源文件。
2. `general_report.md`、`finance_report.md`、`ai_daily_report.md` 是标准日报稿的事实来源，必须原文贴入；历史 `tech_report.md` 只作为兼容输入，内容需要并入 AI 日报。
3. 不要对综合、财经、AI 三个事实板块做二次摘要、改写或统一文风，除非是执行跨板块去重。
4. 如果用户给了某个板块的完整内容，按用户版本原文覆盖。
5. 如果缺少某个源文件或当天数据不足，明确写“数据缺口”，不要编造。
6. 最终默认创建飞书文档并返回链接；对话里只给链接和必要的缺口/授权说明。
7. 如果用户额外要求 PDF，PDF 要保留 Markdown 的原始阅读结构和链接，优先用 HTML 阅读页导出，不要重新设计版式。
8. HTML 导出 PDF 时，浏览器必须直接打开完整 HTML 页面，例如本地 HTTP 地址或可直接访问的 HTML 文件页面；不要把完整 HTML 通过 `data:` URL 塞给浏览器。
9. 不允许把 `reportlab` 作为“HTML 保真导出”的 fallback。它只能用于明确接受重排的程序化 PDF，不适用于 Morning Brief 这类阅读页保真输出。
10. 如果浏览器打印链路失败，必须明确报“PDF 被阻塞 / 未完成”，而不是交付一个样式失真的 fallback PDF 冒充完成品。
11. 标准日报稿主标题默认使用 `Morning Brief | YYYY-MM-DD`。
12. 主标题后不要先放“生成时间 / 数据窗口 / 说明”这类元信息；正文必须直接从 `## 🌅 一、综合早报` 开始。
13. 标准日报稿保留外层章节标题，并去掉各源文件自身的首个 `# 标题` 行，避免重复大标题。
14. 外层章节标题保留 emoji，例如 `🌅 一、综合早报`、`💰 二、财经早报`。
15. “生成时间 / 数据窗口 / 合并来源 / 说明”统一放到全文末尾，用 Markdown 引用块表示，不要再放在开头。
16. 标准日报发布前必须做跨板块去重：先按 `财经 > AI > 科技兼容输入 > 综合` 的顺序检查候选重复，再以“综合早报优先保留”为最终归属原则；如果综合已收录同一事件，财经/AI/科技兼容输入只保留明确不同的价格、政策、模型、论文、产品或交易影响，否则删除重复条目。

## PDF 导出与核对

只有用户要求 PDF 时，才执行本节。Morning Brief 的 PDF 交付前，必须完成下面的固定流程：

1. 先生成完整临时 Markdown。
2. 再渲染成完整 HTML 阅读页，并把 HTML 单独落盘。
3. 让浏览器直接打开该 HTML 页面后打印 PDF。
4. 导出后执行 `pdfinfo`，确认页数没有异常偏少。
5. 导出后执行 `pdftotext`，对比 PDF 尾部文本与 HTML 尾部文本，确保最后一个板块和最后几段内容一致落盘。
6. 用 `pdftoppm -png` 渲染最后 1-2 页，人工确认没有空白、截断、缺页或停在中间章节。

只要 HTML 和 PDF 尾部不一致，就必须视为导出失败，重导，不得交付。
如果浏览器打印根本跑不通，明确说明 PDF 阻塞原因；不得把 Markdown/HTML、`reportlab` 或其他重排版导出物当作“已完成 PDF”。只有用户明确接受时，才可以额外交付 Markdown/HTML。

## 推荐顺序

1. 综合早报
2. 财经早报
3. AI 日报
4. 美股股票早报

## 允许新增的内容

- 标准日报稿标题
- 文末引用式元信息块（生成时间、数据窗口、合并来源、说明）
- 板块标题和分隔线
- 缺口说明
- 飞书文档创建与授权说明

## 保存路径

- 如果用户要求保存文件且指定路径，保存到用户路径。
- 如果用户要求 PDF 但未指定路径，保存到以下兼容路径：
  - `reports/YYYY-MM-DD/morning_brief_YYYY-MM-DD.pdf`

## 过程文件清理

- 允许在同一日期目录或临时目录中创建 Markdown、HTML、JSON、PNG、快照文件。
- PDF 验收通过后，删除本轮生成的过程文件。
- 不要删除用户明确要求保留的文件、历史报告、onboarding 状态或偏好文件。
